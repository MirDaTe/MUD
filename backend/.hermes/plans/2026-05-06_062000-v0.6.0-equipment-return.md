## Phase 1: 모델 확장 (기초 공사)

### Task 1.1: Room 모델에 안전지역 + 여관 필드 추가
- **Files:** `app/models/room.py`
- `is_safe: Boolean` (True=안전지역, 전투 불가)
- `is_inn: Boolean` (True=귀환장소 지정 가능한 여관/주막)
- `return_point: Boolean` (True=이 방이 현재 캐릭터의 귀환지점)
- 기존 방들 중 마을 지역(입문마을 1~22)에 `is_safe=True, is_inn=True`

### Task 1.2: Item 모델에 고유코드 + 장비슬롯 + 중첩제한 확장
- **Files:** `app/models/item.py`
- `code: String(30)` — 고유 아이템 코드 (예: "WPN_SWORD_IRON_01")
- `slot: String(20)` — 장비 슬롯 (head/chest/legs/feet/hands/cloak/necklace/ring/underwear/trinket/mainhand/offhand/twohand)
- `weapon_type: String(20)` — 무기 분류 (sword/blade/spear/staff/bow/dagger 등)
- `stack_limit: Integer` — 최대 중첩 수 (장비=1, 소모품=100)
- `unique_id: String(36)` — 인스턴스별 고유 ID (UUID, 장비 구분용)

### Task 1.3: Inventory 모델 재설계 (장비 슬롯 + 중첩)
- **Files:** `app/models/inventory.py`
- `slot: String(20)` — 장착된 슬롯명 (None = 가방)
- `instance_id: String(36)` — 아이템 인스턴스 고유 ID (장비/강화 추적용)
- `stackable` 필드 제거 → Item.stack_limit 으로 통합

### Task 1.4: Character 모델에 귀환 + 돈 제한 + 장비 슬롯 추가
- **Files:** `app/models/character.py`
- `return_room_id: Integer` — 귀환 지정 방 ID (NULL 허용)
- `max_gold: Integer = 9999999999` — 소지금 상한
- `gold` 세터에서 max_gold 초과 불가 처리 (Python @property + @gold.setter)
- 장비 장착 상태는 Inventory.slot 으로 관리하므로 Character에는 별도 컬럼 불필요

### Task 1.5: 새 모델 Migration + DB 리셋 스크립트
- **Files:** `scripts/reset_db.py`
- 기존 DB 백업 후 새 스키마로 재생성
- `Base.metadata.drop_all()` → `Base.metadata.create_all()`

## 위험 요소

1. **DB 마이그레이션** — SQLite는 ALTER TABLE 제한이 있으므로 drop+recreate 방식 사용
2. **기존 데이터 손실** — 백업 필수
3. **방 ID 충돌** — 신규 방은 103번부터 시작
4. **아이템 ID 충돌** — 신규 아이템은 충분히 큰 ID 대역 사용
5. **장비 스탯 밸런스** — 13슬롯이므로 스탯 합산이 과도해지지 않도록 조정
